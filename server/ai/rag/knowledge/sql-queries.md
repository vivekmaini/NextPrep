# SQL Queries Practice

## SELECT and Filtering
Basic SELECT retrieves data from tables. SELECT column1, column2 FROM table_name. SELECT * retrieves all columns. WHERE filters rows: SELECT * FROM employees WHERE salary > 50000. Comparison operators: =, !=, <, >, <=, >=. IN checks against a list: WHERE department IN ('IT', 'HR', 'Finance'). BETWEEN for range: WHERE salary BETWEEN 30000 AND 60000. LIKE for pattern matching: WHERE name LIKE 'A%' (starts with A), '%son' (ends with son), '%an%' (contains an). _ matches exactly one character. IS NULL checks for null values. AND, OR, NOT combine conditions. ORDER BY sorts results: ORDER BY salary DESC. LIMIT restricts rows returned: LIMIT 10. OFFSET skips rows: LIMIT 10 OFFSET 20.

## JOIN Operations
INNER JOIN: SELECT e.name, d.department_name FROM employees e INNER JOIN departments d ON e.dept_id = d.id. Returns only matching rows from both tables. LEFT JOIN: returns all rows from left table, NULL for non-matching right rows. Useful for finding employees without departments. RIGHT JOIN: returns all rows from right table. FULL OUTER JOIN: returns all rows from both tables. SELF JOIN: join a table with itself. Example: find employees and their managers: SELECT e.name AS employee, m.name AS manager FROM employees e LEFT JOIN employees m ON e.manager_id = m.id. CROSS JOIN: cartesian product of two tables.

## Aggregate Functions and GROUP BY
COUNT(*) counts all rows. COUNT(column) counts non-null values. SUM(salary) adds all salaries. AVG(salary) calculates average. MAX(salary) finds highest. MIN(salary) finds lowest. GROUP BY groups rows for aggregation: SELECT department, COUNT(*) AS emp_count, AVG(salary) AS avg_salary FROM employees GROUP BY department. HAVING filters groups after aggregation: HAVING COUNT(*) > 5. Difference: WHERE filters individual rows before grouping, HAVING filters groups after. Example: departments with average salary above 50000: SELECT department, AVG(salary) FROM employees GROUP BY department HAVING AVG(salary) > 50000.

## Subqueries
Scalar subquery returns single value: SELECT name FROM employees WHERE salary = (SELECT MAX(salary) FROM employees). Row subquery returns single row. Table subquery returns multiple rows: WHERE department IN (SELECT department FROM employees WHERE salary > 70000). Correlated subquery references outer query: SELECT name, salary FROM employees e WHERE salary > (SELECT AVG(salary) FROM employees WHERE department = e.department). EXISTS checks if subquery returns any rows: SELECT name FROM departments d WHERE EXISTS (SELECT 1 FROM employees e WHERE e.dept_id = d.id). NOT EXISTS for inverse.

## Window Functions
Window functions perform calculations across related rows without grouping. ROW_NUMBER() assigns sequential numbers: ROW_NUMBER() OVER (ORDER BY salary DESC). RANK() assigns rank with gaps for ties. DENSE_RANK() assigns rank without gaps. NTILE(n) divides rows into n groups. PARTITION BY creates windows within groups: RANK() OVER (PARTITION BY department ORDER BY salary DESC) ranks employees within each department. LAG(column, n) accesses previous row value. LEAD(column, n) accesses next row value. SUM() OVER() running total. Moving averages: AVG(salary) OVER (ORDER BY hire_date ROWS BETWEEN 2 PRECEDING AND CURRENT ROW).

## Common SQL Interview Queries
Find second highest salary: SELECT MAX(salary) FROM employees WHERE salary < (SELECT MAX(salary) FROM employees). Or using DENSE_RANK: SELECT salary FROM (SELECT salary, DENSE_RANK() OVER (ORDER BY salary DESC) AS rank FROM employees) t WHERE rank = 2. Find duplicate records: SELECT email, COUNT(*) FROM users GROUP BY email HAVING COUNT(*) > 1. Delete duplicates keeping one: DELETE FROM users WHERE id NOT IN (SELECT MIN(id) FROM users GROUP BY email). Find employees earning more than their manager: SELECT e.name FROM employees e JOIN employees m ON e.manager_id = m.id WHERE e.salary > m.salary.

## Data Modification
INSERT INTO table (columns) VALUES (values). Insert multiple rows: INSERT INTO table VALUES (row1), (row2), (row3). INSERT INTO ... SELECT for bulk insert from another table. UPDATE table SET column = value WHERE condition. Always use WHERE in UPDATE and DELETE to avoid modifying all rows. DELETE FROM table WHERE condition. TRUNCATE removes all rows faster than DELETE but cannot be rolled back. UPSERT (INSERT ON CONFLICT in PostgreSQL): INSERT INTO users (email, name) VALUES ('a@b.com', 'Alice') ON CONFLICT (email) DO UPDATE SET name = EXCLUDED.name.

## Table Operations
CREATE TABLE: define columns with types and constraints. Data types: INTEGER, SERIAL (auto-increment), VARCHAR(n), TEXT, BOOLEAN, DATE, TIMESTAMP, JSONB, NUMERIC(p,s). Constraints: PRIMARY KEY, NOT NULL, UNIQUE, FOREIGN KEY, CHECK, DEFAULT. ALTER TABLE: ADD COLUMN, DROP COLUMN, RENAME COLUMN, ALTER COLUMN TYPE, ADD CONSTRAINT. DROP TABLE removes table and data. CREATE INDEX for performance: CREATE INDEX idx_name ON table(column). Unique index: CREATE UNIQUE INDEX. Composite index: CREATE INDEX ON table(col1, col2). Views: CREATE VIEW view_name AS SELECT query. Materialised views store data physically.

## Transactions and Advanced
BEGIN starts a transaction. COMMIT saves changes. ROLLBACK undoes changes. SAVEPOINT creates a checkpoint within a transaction. Common Transaction Control Language (TCL) pattern: BEGIN; UPDATE accounts SET balance = balance - 100 WHERE id = 1; UPDATE accounts SET balance = balance + 100 WHERE id = 2; COMMIT. CASE expression: SELECT name, CASE WHEN salary > 70000 THEN 'High' WHEN salary > 40000 THEN 'Medium' ELSE 'Low' END AS salary_level FROM employees. COALESCE returns first non-null value. CAST converts types. String functions: CONCAT, SUBSTRING, UPPER, LOWER, TRIM, LENGTH, REPLACE. Date functions: NOW(), CURRENT_DATE, EXTRACT, DATE_PART, AGE, INTERVAL.
