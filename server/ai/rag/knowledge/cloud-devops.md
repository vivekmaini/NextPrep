# Cloud Computing and DevOps Concepts

## What is Cloud Computing
Cloud computing delivers computing services (servers, storage, databases, networking, software, analytics, AI) over the internet. Instead of owning and maintaining physical servers, you rent resources from cloud providers. Models: IaaS (Infrastructure as a Service) provides virtual machines, storage, networks — you manage OS and applications (AWS EC2, Google Compute). PaaS (Platform as a Service) provides a platform for deploying applications without managing infrastructure (Heroku, Google App Engine, Render). SaaS (Software as a Service) provides ready-to-use applications (Gmail, Slack, Salesforce). Deployment models: Public cloud (shared infrastructure), Private cloud (dedicated infrastructure), Hybrid cloud (combination).

## AWS Core Services
EC2 (Elastic Compute Cloud): virtual servers in the cloud. Choose instance types based on CPU, memory, and storage needs. S3 (Simple Storage Service): object storage for files, images, backups. Virtually unlimited storage. RDS (Relational Database Service): managed databases (PostgreSQL, MySQL). Handles backups, patching, scaling. Lambda: serverless functions that run code without provisioning servers. Pay only for execution time. API Gateway: create, publish, and manage APIs. CloudFront: CDN for fast content delivery. IAM (Identity and Access Management): manage users, roles, and permissions. VPC (Virtual Private Cloud): isolated network in the cloud. SQS (Simple Queue Service): message queue for decoupling services. DynamoDB: managed NoSQL database.

## Containerisation with Docker
Containers package an application with all its dependencies into a standardised unit. Unlike virtual machines, containers share the host OS kernel, making them lightweight and fast. Docker images are read-only templates that define what goes into a container. Layers: each instruction in a Dockerfile creates a layer. Images are built from layers for efficiency. Docker Hub is a registry for sharing images. Docker Compose orchestrates multi-container applications. Example for NextPrep: one container for Node.js backend, one for PostgreSQL, one for Ollama. Container networking allows containers to communicate. Volumes persist data beyond container lifecycle. Best practices: use small base images (alpine), multi-stage builds, do not run as root, use .dockerignore.

## Kubernetes Basics
Kubernetes (K8s) orchestrates containerised applications at scale. Pod: smallest deployable unit, contains one or more containers. Deployment: manages replicas of pods, handles updates and rollbacks. Service: stable network endpoint for accessing pods. Types: ClusterIP (internal), NodePort (external via node port), LoadBalancer (external via cloud LB). Namespace: logical grouping of resources. ConfigMap and Secret: manage configuration and sensitive data. Ingress: manages external access with routing rules. Horizontal Pod Autoscaler: scales pods based on CPU or custom metrics. Key concepts: desired state vs actual state, declarative configuration with YAML, self-healing (restarts failed pods), rolling updates.

## CI/CD Deep Dive
Continuous Integration: developers merge code frequently, automated builds and tests run on every commit. Catches integration issues early. Continuous Delivery: code is always in a deployable state, release to production is a manual decision. Continuous Deployment: every change that passes tests is automatically deployed to production. Pipeline tools: GitHub Actions (YAML workflows triggered by events), Jenkins (open-source automation server), GitLab CI (built into GitLab), CircleCI, Travis CI. Pipeline stages: lint code, run unit tests, run integration tests, build artifacts, security scanning, deploy to staging, smoke tests, deploy to production. Infrastructure as Code: Terraform, CloudFormation define infrastructure in code.

## Monitoring and Logging
Monitoring tracks application health and performance. Metrics: response time, error rate, CPU usage, memory usage, request throughput. Alerting: notify when metrics exceed thresholds. Logging records events for debugging and auditing. Log levels: ERROR (failures), WARN (potential issues), INFO (normal events), DEBUG (detailed debugging). Structured logging: log as JSON for easy parsing. Centralised logging: aggregate logs from all services (ELK stack: Elasticsearch, Logstash, Kibana). Application Performance Monitoring (APM): traces requests across services, identifies bottlenecks. Health checks: /health endpoint returns service status. Uptime monitoring: regularly check if services are available. Dashboard: visualise metrics and logs (Grafana, Datadog).

## Linux Commands for Interviews
File operations: ls (list), cd (change directory), pwd (print working directory), mkdir (create directory), rm (remove), cp (copy), mv (move), cat (view file), head/tail (first/last lines), find (search files), grep (search content). Permissions: chmod (change permissions), chown (change owner). rwx = read/write/execute for owner/group/others. Process management: ps (list processes), top/htop (real-time monitoring), kill (terminate process), bg/fg (background/foreground). Networking: curl (HTTP requests), wget (download), ping (check connectivity), netstat/ss (network connections), ifconfig/ip (network interfaces). Package management: apt (Debian/Ubuntu), yum (CentOS/RHEL). Shell scripting: bash scripts automate tasks with variables, loops, conditions.

## Networking in Cloud
Virtual Private Cloud (VPC): isolated network in the cloud. Subnets divide a VPC into segments (public and private). Security Groups: virtual firewalls that control inbound and outbound traffic for instances. Network ACLs: stateless firewall at subnet level. NAT Gateway: allows private subnet instances to access the internet without being directly accessible. Elastic IP: static public IP address. Load Balancer: distributes traffic across instances in multiple availability zones. Route 53: DNS service for domain management. CDN (CloudFront): caches content at edge locations globally. VPN: secure connection between on-premises network and cloud. Direct Connect: dedicated network connection to AWS.

## Serverless Computing
Serverless lets you run code without managing servers. Cloud provider handles infrastructure, scaling, and availability. AWS Lambda: run functions triggered by events (API requests, file uploads, database changes, schedules). Pay only for execution time (per millisecond). Limits: max 15 minutes execution, limited memory. Cold start: first invocation after idle period is slower. Serverless databases: DynamoDB, FaunaDB, Neon PostgreSQL. Serverless file storage: S3. API Gateway + Lambda: build complete APIs without servers. Benefits: no infrastructure management, automatic scaling, pay-per-use pricing. Limitations: cold starts, execution time limits, vendor lock-in, harder debugging. Best for: event-driven processing, lightweight APIs, scheduled tasks.
