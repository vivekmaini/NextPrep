# Technical Interview Preparation

## Problem-Solving Approach
When given a technical problem in an interview, follow this structured approach: 1) Clarify the problem by asking questions about inputs, outputs, constraints, and edge cases. Never jump straight into coding. 2) State a brute force approach and its time/space complexity. This shows you have a baseline. 3) Optimise by identifying patterns, redundant work, or better data structures (e.g., using a hash map to reduce O(n) search to O(1)). 4) Walk through your solution with a small example mentally or on the whiteboard before coding. 5) Write clean, modular code. 6) Dry run the code with edge cases (empty input, large input, negative numbers). Always communicate your thinking aloud so the interviewer knows your thought process.

## Time and Space Complexity
Always analyse and state the time and space complexity of your solution using Big-O notation. It describes the worst-case scenario. Common complexities: O(1) constant (hash map lookup), O(log n) logarithmic (binary search), O(n) linear (iterating an array), O(n log n) linearithmic (merge sort, quick sort), O(n²) quadratic (nested loops like bubble sort), O(2^n) exponential (recursive Fibonacci without memoization). Space complexity refers to extra memory used, excluding the input itself. When discussing trade-offs, explain why you chose a particular time-space balance. For example, using a hash map trades O(n) space for O(1) lookups instead of O(n) search in an array.

## Object-Oriented Programming (OOP)
Key OOP concepts for interviews: Encapsulation bundles data and methods together and restricts direct access to internal state using access modifiers (private, protected, public). Inheritance allows a class to reuse and extend the behaviour of a parent class, promoting code reusability. Polymorphism means "many forms"; it allows the same interface to behave differently based on the object type (Method Overloading for compile-time, Method Overriding for runtime). Abstraction hides complex implementation details behind a simple interface (using abstract classes or interfaces). Be ready to explain with real-world examples, such as a Vehicle base class with Car and Bike subclasses that implement their own engine start methods.

## Design Patterns
Design patterns are proven solutions to common software design problems. Creational patterns deal with object creation: Singleton (ensures a class has only one instance, e.g., DB connection), Factory (creates objects without specifying the exact class), Builder (constructs complex objects step by step). Structural patterns deal with object composition: Adapter (allows incompatible interfaces to work together), Decorator (adds behavior to objects dynamically). Behavioral patterns deal with communication between objects: Observer (publish-subscribe mechanism, e.g., event listeners), Strategy (encapsulates interchangeable algorithms). Understand when and why you would use each pattern rather than just memorising definitions.

## System Design and Architecture
For entry-level roles, system design focuses on understanding high-level components. Understand client-server architecture. Know how HTTP requests and responses work. Understand scaling: Vertical scaling (adding more CPU/RAM to a server) vs Horizontal scaling (adding more servers). Load balancing distributes traffic across servers. Caching (e.g., Redis) stores frequently accessed data in memory to reduce database load. Know the basics of databases: SQL (relational, structured, ACID compliant) versus NoSQL (document/key-value, flexible schema, horizontally scalable). Understand microservices (independent, loosely coupled services) vs monolithic architecture (single unified unit).

## API Design (REST vs GraphQL)
RESTful API design principles: Use nouns for endpoints (/users), not verbs (/getUsers). Use HTTP methods correctly: GET for reading, POST for creating, PUT for replacing, PATCH for partial updating, DELETE for removing. Use proper status codes: 200 (OK), 201 (Created), 400 (Bad Request), 401 (Unauthorized), 404 (Not Found), 500 (Internal Server Error). Version your API (e.g., /api/v1/users). Return consistent JSON responses. GraphQL is an alternative to REST where the client specifies exactly what data it needs in a single request, preventing over-fetching and under-fetching of data.

## Database Deep Dive
Common database interview questions: Explain ACID properties (Atomicity: all or nothing, Consistency: valid state transitions, Isolation: concurrent transactions don't interfere, Durability: saved data persists). CAP Theorem states a distributed data store can only provide two of three guarantees: Consistency, Availability, and Partition Tolerance. What is indexing: a data structure (usually B-Tree) that improves query speed at the cost of write speed and storage. What is normalisation: organising data to reduce redundancy (1NF, 2NF, 3NF). Difference between inner join, left join, right join, and full outer join. Be prepared to write SQL queries involving GROUP BY, HAVING, and subqueries.

## Concurrency and Multithreading
Basic concepts: A process is an independent program in execution with its own memory space. A thread is a lightweight unit of execution within a process, sharing the same memory. Concurrency is dealing with multiple things at once (time-slicing), while parallelism is doing multiple things at exactly the same time (multi-core). Race condition occurs when multiple threads access shared data concurrently and the outcome depends on execution order. Prevent this using synchronization mechanisms like Mutexes (locks) or Semaphores. Deadlock occurs when threads wait for each other to release locks in a circular chain.

## Testing Knowledge
Understand different types of testing: Unit tests verify individual functions or methods in isolation using mocks/stubs. Integration tests verify that different modules or services work together correctly (e.g., API + Database). End-to-end (E2E) tests verify the complete user flow from the UI to the backend. Test-Driven Development (TDD) is a process where you write the failing test first, write code to pass it, and then refactor. Code coverage measures the percentage of code executed by tests. Be able to explain how you would test a specific function, including edge cases, null inputs, and error scenarios.

## Version Control (Git)
Understand Git fundamentals for interviews: A branch represents an independent line of development. The difference between merge (preserves branch history with a merge commit) and rebase (moves your commits to the tip of the target branch for a linear history). What is a pull request (PR): proposing changes to be merged into another branch, usually accompanied by code review. How to resolve merge conflicts: open the conflicting file, choose which changes to keep, remove Git markers, and commit. Common commands: git add, commit, push, pull, branch, checkout, merge, rebase, stash, cherry-pick.

## Networking Basics
Common networking questions: What happens when you type a URL in the browser (DNS lookup, TCP 3-way handshake, HTTP request sent, server processes and sends HTTP response, browser renders HTML/CSS/JS). Difference between HTTP and HTTPS (HTTPS uses TLS/SSL to encrypt the payload). What is TCP (reliable, connection-oriented, ordered delivery) versus UDP (fast, connectionless, unreliable delivery - used for video streaming/gaming). What is CORS (Cross-Origin Resource Sharing): a security feature implemented by browsers that restricts web pages from making requests to a different domain than the one that served the web page.

## Security Concepts
Interview security questions (OWASP Top 10 basics): What is SQL injection and how to prevent it (use parameterized queries or prepared statements, never concatenate strings). What is XSS (Cross-Site Scripting) and how to prevent it (sanitize user input, escape output before rendering). What is CSRF (Cross-Site Request Forgery) and how to prevent it (use anti-CSRF tokens). What is JWT (JSON Web Token) and how token-based authentication works. What is the difference between hashing (one-way transformation, used for passwords with bcrypt) and encryption (two-way transformation with a key, used for data in transit/rest).
