# Web Development Interview Preparation

## React Fundamentals
React is a JavaScript library for building user interfaces using a component-based architecture. Components are reusable, independent pieces of UI. Functional components use hooks for state and lifecycle management. JSX is a syntax extension that allows writing HTML-like code in JavaScript. Virtual DOM is React's in-memory representation of the actual DOM. React compares the virtual DOM with the previous version (diffing) and updates only the changed parts (reconciliation), making UI updates efficient. React uses a unidirectional data flow where data flows from parent to child via props. Components re-render when their state or props change. React.memo prevents unnecessary re-renders of functional components by memoising the output.

## React Component Lifecycle
In class components: mounting (constructor, render, componentDidMount), updating (shouldComponentUpdate, render, componentDidUpdate), unmounting (componentWillUnmount). In functional components with hooks: useEffect with empty dependency array runs once after mount (like componentDidMount). useEffect with dependencies runs when those values change (like componentDidUpdate). useEffect cleanup function runs on unmount (like componentWillUnmount). useEffect without dependency array runs after every render. Common pattern: fetch data in useEffect on mount, clean up subscriptions in return function. useLayoutEffect runs synchronously after DOM mutations but before browser paint, useful for measurements.

## React Hooks Deep Dive
useState: const [value, setValue] = useState(initialValue). Updater function for state based on previous: setValue(prev => prev + 1). Lazy initialisation: useState(() => expensiveComputation()). useEffect: handles side effects. Dependencies array controls when effect runs. Empty array means run once. No array means every render. Cleanup returns a function. useContext: accesses context value. Create context with createContext, provide with Provider, consume with useContext. useRef: persists mutable value across renders without causing re-render. Access DOM elements: ref.current. useMemo: caches computed value: useMemo(() => expensiveCalc(a, b), [a, b]). useCallback: caches function reference: useCallback(() => doSomething(id), [id]). useReducer: alternative to useState for complex state logic: const [state, dispatch] = useReducer(reducer, initialState). Custom hooks: extract reusable logic. Must start with "use". Example: useLocalStorage, useFetch, useDebounce, useWindowSize.

## React State Management Patterns
Local state: useState for component-specific data. Lifting state up: move shared state to nearest common ancestor, pass down via props. Prop drilling problem: passing props through many intermediate components that do not use them. Solution 1: Context API. Create a context, wrap components with Provider, consume with useContext. Best for: theme, auth, language. Not ideal for frequently changing data. Solution 2: useReducer + Context for complex state with multiple actions. Define actions as types, reducer handles state transitions. Solution 3: External state managers. Redux: single store, actions, reducers, predictable state. Redux Toolkit simplifies Redux with createSlice. Zustand: simpler alternative, minimal boilerplate. Jotai: atomic state management. React Query / TanStack Query: server state management, caching, refetching, background updates.

## React Router
React Router enables client-side routing in single-page applications. BrowserRouter wraps the app. Routes component contains Route definitions. Route maps URL path to a component. Link and NavLink for navigation without full page reload. NavLink adds active styling. useNavigate hook for programmatic navigation. useParams extracts URL parameters: /users/:id. useSearchParams for query strings. useLocation accesses current URL information. Nested routes: parent route renders Outlet where child routes appear. Protected routes: wrap routes with authentication check component that redirects to login if not authenticated. Lazy loading routes with React.lazy and Suspense for code splitting. 404 handling: Route with path="*" catches unmatched URLs.

## React Performance Optimisation
React.memo: wraps component to skip re-render if props have not changed. useMemo: caches expensive computations. useCallback: prevents child re-renders caused by new function references. Code splitting: React.lazy() and Suspense load components on demand, reducing initial bundle size. Virtualisation: react-window or react-virtualized for rendering large lists efficiently by only rendering visible items. Debouncing: delay expensive operations (search input) until user stops typing. useTransition: marks state updates as non-urgent, keeping UI responsive. Key prop: use stable unique keys in lists, never use index as key if list can change. Avoid inline object and function creation in JSX. Profile with React DevTools Profiler to identify slow components.

## React Forms and Validation
Controlled components: form inputs controlled by React state. Value comes from state, onChange updates state. Uncontrolled components: DOM handles form state, use ref to access values. React Hook Form: popular library for performant forms with minimal re-renders. Formik: another form library with built-in validation. Yup: schema-based validation library often used with Formik or React Hook Form. Client-side validation: check required fields, email format, password strength, matching passwords. Always validate on server too. Form submission: prevent default, collect form data, send API request, handle loading state, display success or error message. Debounce validation for better UX on text inputs.

## Node.js Fundamentals
Node.js is a JavaScript runtime built on Chrome's V8 engine. It uses a single-threaded event loop with non-blocking IO, making it efficient for IO-heavy applications like web servers and APIs. The event loop processes callbacks from the event queue after the call stack is empty. Phases of event loop: timers (setTimeout/setInterval callbacks), pending callbacks (IO callbacks deferred from previous cycle), idle/prepare (internal), poll (retrieve new IO events), check (setImmediate callbacks), close callbacks. process.nextTick runs before the next event loop phase. Node.js is not suitable for CPU-intensive tasks like heavy computation because it blocks the single thread. Solution: worker threads for CPU-intensive tasks. CommonJS: require() and module.exports. ES Modules: import and export (with "type": "module" in package.json or .mjs extension).

## Node.js Core Modules
fs (File System): readFile, writeFile, readdir, stat, mkdir, unlink. Async versions for non-blocking IO. fs.promises for promise-based API. path: join (combine paths), resolve (absolute path), basename, dirname, extname. http: create servers and make requests. Low-level module, Express is built on top. events: EventEmitter class for custom events. emit(event, data), on(event, callback). Many Node.js objects are EventEmitters. stream: process data in chunks without loading entire content into memory. Types: Readable, Writable, Duplex, Transform. Used for file processing, HTTP requests, piping data. Buffer: handle binary data. crypto: hashing (createHash), encryption, random bytes. os: operating system info (cpus, memory, platform). util: promisify converts callback-based functions to promises.

## Express.js Deep Dive
Express is a minimal, flexible web framework for Node.js. app.use() registers middleware. Middleware execution order matters. Request lifecycle: incoming request → middleware chain → route handler → response. Error-handling middleware has four parameters: (err, req, res, next). Router: modular route handling. express.Router() creates a mini-app with its own middleware and routes. Mount with app.use('/api/users', userRouter). Request object: req.params (URL parameters), req.query (query string), req.body (parsed body), req.headers, req.cookies, req.file (uploaded file with multer). Response object: res.json() (send JSON), res.status() (set status code), res.send() (send response), res.redirect() (redirect), res.cookie() (set cookie). Template engines: EJS, Pug, Handlebars for server-rendered views. CORS: app.use(cors()) or configure specific origins.

## Express Middleware Patterns
Authentication middleware: verify JWT token from Authorization header, attach user to request. Rate limiting middleware: track request count per IP using in-memory store or Redis, return 429 if limit exceeded. Validation middleware: use Joi or express-validator to validate request body, params, and query. Logging middleware: log request method, URL, status code, response time using morgan or custom logger. Error handling middleware: centralised error handler catches errors from all routes. File upload middleware: multer handles multipart/form-data for file uploads. Compression middleware: compress responses for faster transfer. Helmet middleware: sets security-related HTTP headers. Request parsing: express.json() for JSON bodies, express.urlencoded() for form data.

## RESTful API Design Best Practices
Use nouns for endpoints: /api/users, /api/posts, not /api/getUsers. Use HTTP methods: GET (read), POST (create), PUT (full update), PATCH (partial update), DELETE (remove). Proper status codes: 200 OK, 201 Created, 204 No Content, 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found, 409 Conflict, 422 Unprocessable Entity, 429 Too Many Requests, 500 Internal Server Error. Consistent response format: { success: true/false, message: "...", data: {} }. Pagination: use query params ?page=1&limit=10. Return total count and next/prev links. Filtering and sorting: ?status=active&sort=-createdAt. API versioning: /api/v1/users. HATEOAS: include links to related resources. Rate limiting: include X-RateLimit headers. Idempotency: GET, PUT, DELETE should be idempotent.

## Database Integration with Node.js
PostgreSQL with pg: create connection pool for reuse, use parameterised queries to prevent SQL injection. Pool.query('SELECT * FROM users WHERE id = $1', [userId]). Transactions: const client = await pool.connect(); await client.query('BEGIN'); ...operations...; await client.query('COMMIT'); client.release(). Error handling: ROLLBACK on failure. Connection string: postgresql://user:password@host:port/database. Migrations: track database schema changes in version control. Use tools like node-pg-migrate or knex migrations. Seeding: populate database with initial or test data. MongoDB with mongoose: define schemas, create models, CRUD operations. Redis for caching: set/get key-value pairs, set expiry with EX. ORMs: Prisma (type-safe, auto-generated client), Sequelize (traditional ORM), Drizzle (lightweight). Raw SQL vs ORM: raw SQL gives more control and performance, ORM provides convenience and safety.

## Authentication Implementation
Registration flow: validate input, check if email exists, hash password with bcrypt (salt rounds 10-12), save user to database, generate JWT, return token. Login flow: validate input, find user by email, compare password with bcrypt.compare, generate JWT with user ID and role, return token. JWT structure: header (algorithm, type), payload (user data, issued at, expiry), signature. Token storage: httpOnly cookie (most secure, prevents XSS) or localStorage (vulnerable to XSS but easier). Refresh tokens: short-lived access token (15-30 min) + long-lived refresh token (7-30 days). When access token expires, use refresh token to get new access token without re-login. OAuth 2.0: redirect to provider (Google, GitHub), receive authorization code, exchange for tokens, get user info. Middleware: extract token from header, verify with jwt.verify, attach user to request, call next().

## Error Handling in Node.js
Synchronous errors: try-catch blocks. Async errors with callbacks: error-first callback pattern (err, result). Async errors with promises: .catch() or try-catch with async/await. Unhandled rejections: process.on('unhandledRejection', handler). Uncaught exceptions: process.on('uncaughtException', handler). Custom error classes: extend Error with statusCode and isOperational properties. Operational errors (expected): invalid input, database connection lost, API timeout. Handle gracefully with proper response. Programming errors (bugs): undefined variable, wrong type. Fix the code. Express error handling: pass error to next(error), centralised error handler middleware sends appropriate response. Never expose stack traces or internal details in production. Log errors with structured logging for debugging.

## Testing Node.js Applications
Jest: popular testing framework for Node.js and React. Test files: *.test.js or *.spec.js. describe() groups tests, it() or test() defines individual tests. Assertions: expect(value).toBe(), .toEqual(), .toBeTruthy(), .toThrow(). beforeEach/afterEach for setup/teardown. Mocking: jest.mock() replaces modules, jest.fn() creates mock functions, jest.spyOn() monitors function calls. Supertest: test Express API endpoints. const response = await request(app).get('/api/users').expect(200). Test database: use separate test database or in-memory database. Coverage: jest --coverage generates report. Testing pyramid: many unit tests (services, utilities), fewer integration tests (API endpoints), fewest E2E tests.

## WebSocket and Real-time Communication
HTTP is request-response, client always initiates. WebSocket provides full-duplex communication over a single TCP connection. Server can push data to clients without polling. Socket.IO: popular library for real-time communication. Handles fallbacks (long polling) when WebSocket is not available. Server: io.on('connection', socket => {}). Client: socket.emit('event', data), socket.on('event', callback). Rooms: group clients for targeted messaging. Namespaces: separate communication channels. Use cases: chat applications, live notifications, collaborative editing, real-time dashboards, multiplayer games. Server-Sent Events (SSE): one-way server-to-client streaming over HTTP. Simpler than WebSocket when bidirectional communication is not needed. Long polling: client repeatedly requests, server holds response until data is available. Least efficient but works everywhere.
