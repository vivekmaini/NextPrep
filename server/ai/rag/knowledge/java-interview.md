# Java Interview Preparation

## Java Fundamentals
Java is a statically typed, object-oriented, platform-independent language. Java code compiles to bytecode that runs on the JVM (Java Virtual Machine), enabling "write once, run anywhere." Java is strongly typed and every variable must be declared with its type. Primitive types: byte (8-bit), short (16-bit), int (32-bit), long (64-bit), float (32-bit), double (64-bit), boolean, char (16-bit Unicode). Wrapper classes (Integer, Double, Boolean) allow primitives to be used as objects. Autoboxing automatically converts between primitive and wrapper. Java uses pass-by-value for all arguments. For objects, the reference value (memory address) is passed by value.

## OOP in Java
Encapsulation: bundling data and methods together, using access modifiers to control access. Private fields with public getters and setters. Inheritance: a subclass extends a parent class using the extends keyword. Java supports single inheritance only (one parent class). Polymorphism: compile-time (method overloading, same method name with different parameters) and runtime (method overriding, subclass provides specific implementation of parent method). Abstraction: abstract classes can have both abstract and concrete methods. Interfaces define a contract with abstract methods that implementing classes must provide. Since Java 8, interfaces can have default and static methods. Since Java 9, interfaces can have private methods.

## Collections Framework
List: ordered, allows duplicates. ArrayList uses dynamic array, fast random access O(1), slow insertion O(n). LinkedList uses doubly linked list, fast insertion O(1) at known position, slow random access O(n). Set: no duplicates. HashSet uses hash table, O(1) operations, unordered. LinkedHashSet maintains insertion order. TreeSet maintains sorted order, O(log n) operations. Map: key-value pairs. HashMap is O(1) for get/put, unordered. LinkedHashMap maintains insertion order. TreeMap maintains sorted key order, O(log n). Queue: FIFO. PriorityQueue sorts by natural order or comparator. Deque supports both ends. ConcurrentHashMap is thread-safe. Collections.unmodifiableList creates read-only views.

## Exception Handling
Java has checked exceptions (must be caught or declared with throws) and unchecked exceptions (runtime exceptions, not required to handle). Exception hierarchy: Throwable is the root. Error represents serious JVM problems (OutOfMemoryError, StackOverflowError). Exception is the base for application exceptions. RuntimeException and its subclasses are unchecked (NullPointerException, ArrayIndexOutOfBoundsException, ClassCastException). Try-catch-finally: try contains risky code, catch handles specific exceptions, finally always executes for cleanup. Try-with-resources (Java 7+) automatically closes resources implementing AutoCloseable. Custom exceptions extend Exception (checked) or RuntimeException (unchecked).

## Multithreading
A thread is a lightweight unit of execution. Creating threads: extend Thread class and override run(), or implement Runnable interface and pass to Thread constructor. Thread states: NEW, RUNNABLE, BLOCKED, WAITING, TIMED_WAITING, TERMINATED. Synchronisation prevents race conditions. synchronized keyword locks a method or block so only one thread can access it. wait() releases the lock and waits. notify() wakes one waiting thread. notifyAll() wakes all. volatile keyword ensures visibility of changes across threads. Thread pool: ExecutorService manages a pool of reusable threads. Callable returns a result and can throw exceptions, unlike Runnable. Future represents the result of an async computation. Deadlock prevention: acquire locks in a consistent order, use timeouts, avoid nested locks.

## String Handling
String is immutable in Java. Every modification creates a new String object. String pool: Java maintains a pool of string literals for memory efficiency. Strings created with literals are checked against the pool. == compares references, equals() compares content. Always use equals() for string comparison. StringBuilder is mutable and not thread-safe, good for single-threaded string concatenation. StringBuffer is mutable and thread-safe. String methods: length(), charAt(), substring(), indexOf(), contains(), replace(), split(), trim(), toLowerCase(), toUpperCase(), startsWith(), endsWith(). String.format and printf for formatted output.

## Java 8 Plus Features
Lambda expressions provide concise anonymous function syntax: (parameters) -> expression. Functional interfaces have exactly one abstract method (Predicate, Function, Consumer, Supplier). Stream API processes collections declaratively: filter, map, reduce, collect, forEach, sorted, distinct. Streams are lazy and can be parallel. Optional avoids NullPointerException: Optional.of, Optional.ofNullable, isPresent(), orElse(), ifPresent(), map(), flatMap(). Method references: Class::method. Default methods in interfaces allow adding new methods without breaking implementations. Date and Time API (java.time): LocalDate, LocalTime, LocalDateTime, Instant, Duration, Period replace the old Date and Calendar classes.

## JVM and Memory
JVM memory areas: Heap (objects and arrays, shared among threads), Stack (method frames, local variables, one per thread), Method Area (class metadata, static variables), PC Register (current instruction per thread), Native Method Stack. Garbage collection automatically reclaims memory from unreachable objects. GC algorithms: Serial, Parallel, CMS (Concurrent Mark Sweep), G1 (Garbage First). Young generation (Eden, Survivor spaces) for short-lived objects. Old generation for long-lived objects. Minor GC cleans young generation. Major GC cleans old generation. OutOfMemoryError occurs when JVM cannot allocate memory. Memory leaks can still happen if objects are referenced but no longer needed.

## Design Patterns in Java
Singleton: ensure one instance using private constructor and static getInstance(). Factory: create objects without specifying exact class. Abstract Factory: factory of factories. Builder: construct complex objects step by step. Observer: event notification pattern using listeners. Strategy: select algorithm at runtime by injecting different strategy implementations. Adapter: convert one interface to another. Decorator: add behaviour dynamically by wrapping objects. Template Method: define algorithm skeleton in base class, let subclasses override specific steps. Iterator: traverse a collection without exposing its structure. MVC: Model-View-Controller separates data, presentation, and control logic.
