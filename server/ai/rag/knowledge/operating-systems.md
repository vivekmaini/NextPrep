# Operating Systems

## Process vs Thread
A process is an independent program in execution with its own memory space, code, data, and system resources. A thread is a lightweight unit of execution within a process that shares the process's memory and resources. Multiple threads in a process can run concurrently. Creating a thread is faster than creating a process because threads share memory. Inter-thread communication is easier than inter-process communication because threads share the same address space. Context switching between threads is faster than between processes.

## Process States
A process goes through several states during its lifecycle. New: the process is being created. Ready: the process is waiting to be assigned to a CPU. Running: the process is currently being executed by the CPU. Waiting (Blocked): the process is waiting for an IO operation or event to complete. Terminated: the process has finished execution. The operating system's scheduler moves processes between these states based on scheduling algorithms and system events.

## CPU Scheduling Algorithms
First Come First Served (FCFS): processes are executed in the order they arrive. Simple but can cause the convoy effect where short processes wait behind long ones. Shortest Job First (SJF): the process with the shortest burst time is executed first. Optimal for minimising average waiting time but requires knowing burst times in advance. Round Robin (RR): each process gets a fixed time quantum. If not finished, it goes back to the ready queue. Good for time-sharing systems. Fair but high context switching overhead if quantum is too small. Priority Scheduling: each process has a priority. Higher priority processes execute first. Can cause starvation of low-priority processes, solved by aging. Multilevel Queue Scheduling: processes are divided into categories with different queues and scheduling algorithms.

## Deadlock
A deadlock occurs when two or more processes are waiting for each other to release resources, creating a circular dependency where none can proceed. Four necessary conditions for deadlock: Mutual Exclusion (a resource can only be held by one process), Hold and Wait (a process holding a resource waits for another), No Preemption (resources cannot be forcibly taken), Circular Wait (a circular chain of processes each waiting for a resource held by the next). Prevention: break any one condition. Avoidance: use Banker's algorithm to ensure safe state. Detection and recovery: detect cycles in resource allocation graph and terminate or preempt.

## Memory Management
Memory management allocates and manages main memory for processes. Contiguous allocation: each process gets a single contiguous block. Causes external fragmentation. Paging: memory is divided into fixed-size frames and processes into pages. Eliminates external fragmentation. Page table maps virtual pages to physical frames. Segmentation: memory is divided into variable-size segments based on logical divisions like code, data, stack. Virtual memory: allows processes to use more memory than physically available by using disk as extension. Pages are loaded on demand (demand paging). Page fault occurs when a referenced page is not in memory. Page replacement algorithms: FIFO, LRU (Least Recently Used), Optimal. Thrashing occurs when the system spends more time paging than executing.

## File Systems
A file system organises and manages files on storage devices. File operations: create, read, write, delete, seek, truncate. Directory structure: single-level, two-level, tree-structured, acyclic graph. File allocation methods: contiguous (fast access but fragmentation), linked (no fragmentation but slow random access), indexed (uses index block, balanced). Free space management: bit vector, linked list, grouping, counting. Important concepts: inodes in Unix store file metadata, journaling prevents data corruption on crashes, permissions control access (read, write, execute for owner, group, others).

## Synchronisation
Process synchronisation coordinates access to shared resources. Race condition occurs when multiple processes access shared data concurrently and the outcome depends on execution order. Critical section is the code segment that accesses shared resources. Requirements for a solution: mutual exclusion, progress, and bounded waiting. Mutex is a locking mechanism that allows only one thread to access a resource. Semaphore is a signaling mechanism. Binary semaphore works like a mutex. Counting semaphore allows a fixed number of concurrent accesses. Classic problems: Producer-Consumer (bounded buffer), Readers-Writers, Dining Philosophers. Monitors provide a higher-level synchronisation construct with condition variables.

## System Calls
System calls are the interface between user programs and the operating system kernel. Process control: fork creates a new process, exec replaces the current process image, wait makes a parent wait for child termination, exit terminates a process. File operations: open, read, write, close, create, delete. Device management: request device, release device. Information maintenance: get time, get process ID. Communication: pipe, shared memory, message passing. System calls switch execution from user mode to kernel mode for security.

## Disk Scheduling
Disk scheduling algorithms determine the order in which disk IO requests are serviced. FCFS: requests served in arrival order. Simple but high seek time. SSTF (Shortest Seek Time First): the request closest to the current head position is served next. Better average seek time but can cause starvation. SCAN (Elevator): the head moves in one direction servicing requests, then reverses. Fair and no starvation. C-SCAN (Circular SCAN): the head moves in one direction, then jumps back to the beginning. More uniform wait times. LOOK and C-LOOK: similar to SCAN and C-SCAN but reverse direction at the last request instead of going to the disk end.
